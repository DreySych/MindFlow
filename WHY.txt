В приложении ИИ‑поиска используется паттерн проектирования «Стратегия».

Где реализован паттерн:
    Файл ai/strategies.py:
        SearchStrategy — абстрактный интерфейс стратегии.
        AllQuestionsStrategy — стратегия «взять все вопросы».
        LastNQuestionsStrategy — стратегия «взять только последние N вопросов».

    Файл ai/services.py:
        AiSearchService — Context для паттерна «Стратегия».
        В конструкторе AiSearchService принимает объект SearchStrategy и хранит его в self.strategy.
        Метод set_strategy(self, strategy) позволяет менять стратегию.
        Внутри search() сервис не знает деталей выборки постов, а просто вызывает self.strategy.get_questions(user_query).

    Файл ai/views.py:
        В ai_search_api перед вызовом service.search(query) выбирается нужная стратегия.

Зачем:
    Разделение ответственностей:
        AiSearchService отвечает только за общую операцию ИИ‑поиска (сбор контекста, формирование промпта, запрос к Ollama),
        а выбор конкретного набора вопросов вынесен в отдельные стратегии (AllQuestionsStrategy, LastNQuestionsStrategy). Это
        уменьшает связность и упрощает чтение и поддержку кода.

    Взаимозаменяемые алгоритмы поиска:
        Разные способы отбора постов (все вопросы, только последние N, в будущем — по рейтингу, только с ответами и т.п.)
        реализуются как отдельные классы, но имеют общий интерфейс SearchStrategy. Это позволяет добавлять новые варианты
        поиска без переписывания сервиса и views.py.

В итоге паттерн «Стратегия» здесь применяется для изоляции алгоритмов выбора контента для LLM от общей логики ИИ‑поиска
и для обеспечения лёгкого расширения и переключения режимов поиска в системе.
