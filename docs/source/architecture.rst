Архитектура проекта
===================

Общее описание
--------------

MindFlow построен как модульный Django-проект. Каждый крупный блок функционала вынесен в отдельное приложение. Это упрощает поддержку, тестирование и развитие проекта.

Слои приложения
---------------

.. code-block:: text

   Пользовательский интерфейс
   ├── HTML-шаблоны
   ├── CSS
   └── JavaScript
          │
          ▼
   Django views
   ├── обработка HTTP-запросов
   ├── проверка прав
   ├── AJAX/JSON-ответы
   └── подготовка контекста для шаблонов
          │
          ▼
   Формы, сервисы и стратегии
   ├── валидация данных
   ├── AI-поиск
   ├── загрузка модели эмбеддингов
   └── работа с внешним AI API
          │
          ▼
   Модели и база данных
   ├── пользователи
   ├── посты
   ├── комментарии
   ├── лайки
   ├── жалобы
   ├── уведомления
   └── сообщения

Приложения проекта
------------------

.. list-table::
   :header-rows: 1
   :widths: 25 75

   * - Приложение
     - Назначение
   * - ``main``
     - Главная страница, semantic search, лента рекомендаций, фильтрация по тегам, голосование за посты.
   * - ``questions``
     - Создание, редактирование, удаление постов, комментарии, ответы, теги, загрузка изображений.
   * - ``users``
     - Регистрация, авторизация, профили, настройки, подписки, восстановление пароля.
   * - ``complaints``
     - Создание жалоб, панель модерации, принятие и отклонение жалоб.
   * - ``notifications``
     - Список уведомлений, количество непрочитанных, отметка уведомлений как прочитанных.
   * - ``private_messages``
     - Личные сообщения и WebSocket-чат.
   * - ``ai``
     - AI-поиск, стратегии выбора контекста, адаптер внешнего AI API.
   * - ``basic_templates``
     - Общие элементы интерфейса: header, sidebar, footer и базовые шаблоны.

Потоки данных
-------------

Создание поста
~~~~~~~~~~~~~~

.. code-block:: text

   Форма создания поста
        ↓
   QuestionForm
        ↓
   question_make_page
        ↓
   create_question_from_form
        ↓
   сохранение Question + embedding + изображений
        ↓
   редирект в профиль пользователя

Поиск по постам
~~~~~~~~~~~~~~~

.. code-block:: text

   Поисковый запрос
        ↓
   main.views.perform_search
        ↓
   загрузка модели через get_model()
        ↓
   сравнение embedding запроса с embedding постов
        ↓
   сортировка по релевантности и дате
        ↓
   вывод результатов на главной странице

AI-поиск
~~~~~~~~

.. code-block:: text

   Запрос пользователя
        ↓
   ai.views.ai_search_api
        ↓
   выбор SearchStrategy
        ↓
   AiSearchService
        ↓
   сбор контекста из постов, комментариев и ответов
        ↓
   OpenRouter API
        ↓
   JSON-ответ пользователю

WebSocket-чат
~~~~~~~~~~~~~

.. code-block:: text

   Пользователь отправляет сообщение
        ↓
   JavaScript WebSocket
        ↓
   private_messages.consumers.ChatConsumer
        ↓
   сохранение Message
        ↓
   отправка сообщения участникам чата

Ключевые архитектурные решения
------------------------------

* Работа с AI-поиском разделена на стратегии и сервис.
* Модель эмбеддингов загружается через фабричную функцию ``get_model``.
* Внешний AI API отделён через адаптер ``OpenRouterClient``.
* Проверки доступа выполняются во views перед изменением данных.
* Для опасных действий используется POST-запрос.
* Изображения ограничиваются по типу и размеру.
* Lazy loading уменьшает нагрузку при открытии главной страницы и чата.
