Безопасность
============

Хранение секретов
-----------------

Секретные значения должны храниться в ``.env`` и не должны попадать в репозиторий. В проекте используются переменные окружения для:

* ``SECRET_KEY``;
* ``DEBUG``;
* ``EMAIL_HOST_USER``;
* ``EMAIL_HOST_PASSWORD``;
* ``OPENROUTER_API_KEY``.

В репозитории должен храниться только пример файла окружения — ``.env.example``.

Режим DEBUG
-----------

Для локальной разработки допускается:

.. code-block:: bash

   DEBUG=True

Для production-сервера необходимо:

.. code-block:: bash

   DEBUG=False

Проверка прав
-------------

В проекте используются проверки:

* пользователь авторизован;
* пользователь не заблокирован;
* пользователь является автором объекта;
* пользователь является сотрудником/модератором для действий с жалобами.

Удаление постов
---------------

Удаление поста выполняется только через POST-запрос. Перед удалением проверяется, что пользователь является автором поста или staff-пользователем.

Жалобы и модерация
------------------

Принятие и отклонение жалоб выполняется только через POST. Внутри view проверяется, что пользователь авторизован и имеет права staff.

CSRF
----

Django CSRF middleware включён. Для POST-форм используются CSRF-токены. AJAX-запросы, которые изменяют состояние, должны передавать CSRF-токен.

Загрузка изображений
--------------------

При загрузке изображений проверяется:

* MIME-тип файла;
* размер файла;
* количество изображений.

Разрешённые типы:

* JPEG;
* PNG;
* WEBP.

Защита от XSS
-------------

Для динамического вывода сообщений в чате используется безопасная вставка через ``textContent`` и ``createTextNode``. Это предотвращает выполнение HTML/JavaScript, отправленного пользователем в тексте сообщения.

Ограничения AI
--------------

AI-функционал зависит от внешнего API. Для устойчивости используется fallback-логика: если внешний сервис недоступен, проект не падает, а выбирает безопасный вариант ответа или тега.
