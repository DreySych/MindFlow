Паттерны проектирования
=======================

В проекте используются три паттерна проектирования: Strategy, Factory Method и Adapter.

Strategy
--------

Где реализован
~~~~~~~~~~~~~~

* ``ai/strategies.py``
* ``ai/services.py``
* ``ai/views.py``

Основные классы:

* ``SearchStrategy`` — общий интерфейс стратегии;
* ``AllQuestionsStrategy`` — стратегия выбора всех вопросов;
* ``LastNQuestionsStrategy`` — стратегия выбора последних N вопросов;
* ``AiSearchService`` — context, который использует выбранную стратегию.

Зачем используется
~~~~~~~~~~~~~~~~~~

AI-поиск может работать с разными способами выбора контекста. Например, можно передать в LLM все посты или только последние N постов.

Паттерн Strategy позволяет менять алгоритм выбора вопросов без переписывания ``AiSearchService``.

Factory Method
--------------

Где реализован
~~~~~~~~~~~~~~

* ``main/model_loader.py``
* ``main/views.py``
* ``questions/views.py``

Функция ``get_model()`` отвечает за получение модели эмбеддингов. Остальной код не создаёт модель напрямую, а получает её через единый метод.

Зачем используется
~~~~~~~~~~~~~~~~~~

Создание модели машинного обучения вынесено в отдельную фабричную функцию. Это уменьшает дублирование и позволяет заменить модель или способ загрузки в одном месте.

Adapter
-------

Где реализован
~~~~~~~~~~~~~~

* ``ai/clients.py``
* ``ai/services.py``

Класс ``OpenRouterClient`` скрывает детали работы с внешним API OpenRouter и приводит внешний JSON-ответ к понятному внутреннему формату.

Зачем используется
~~~~~~~~~~~~~~~~~~

OpenRouter возвращает данные в собственном формате. Приложению не нужно знать все детали внешнего API. Через адаптер проект получает простой результат: текст ответа или ошибку.

Это упрощает замену AI-провайдера в будущем: вместо переписывания всего AI-поиска достаточно изменить адаптер.
